01 / AI ASSISTANTS

1DotDev

Implemented · hardening

Node.js / SQLite / WhatsApp Cloud API / Claude

An assistant with a memory.

A WhatsApp-native assistant with user-specific history, remembered facts, notes, reminders, and usage tracking.

The problem

Bring everyday assistant tasks into an existing messaging interface, while keeping each user’s state separate.

What I built

A Node.js webhook bridge, signature verification, sender allowlists, command routing, SQLite persistence, and scheduled reminders.

Engineering notes +

Decisions

Keep the service small: a single bridge and SQLite, with explicit per-user records and a command layer alongside model-based routing.

Evidence

The public source includes the webhook handler, command modules, database schema, and deployment documentation.

Current limits

Deployment documentation describes a personal service. Independent uptime and delivery guarantees have not been established by the repository review.

Next focus

Durable message processing, duplicate-delivery handling, restart recovery, and isolation tests.

02 / DATA PIPELINES

AI Systems Radar

Implemented · tested

TypeScript / TF-IDF / Node.js / GitHub Actions

Less noise. Better reading.

An automated reading list that collects, deduplicates, groups, and ranks AI systems news and research.

The problem

Turn a scattered set of research feeds, engineering blogs, and community signals into a manageable reading list.

What I built

Source adapters, freshness filters, TF-IDF similarity, clustering, diversity-aware selection, and a scheduled publishing workflow.

Engineering notes +

Decisions

Use a statistical pipeline and source-derived text instead of an LLM dependency. Preserve source attribution and distinguish community signals from primary sources.

Evidence

The repository review ran all 10 scoring tests successfully and passed the TypeScript check. GitHub Actions tests the pipeline before publishing.

Current limits

Passing tests establish specific pipeline behaviors; they do not establish that the reading recommendations are consistently useful.

Next focus

Evaluate relevance and diversity against a small human-reviewed reading set.

03 / AGENTS & INTEGRATION

DriveSuite

In development

Python / Node.js / SQLite / Docker / MCP scaffold

One conversation. A connected stack.

A home-media assistant project spanning messaging, service integrations, orchestration, and self-hosted infrastructure.

The problem

Make a collection of media services easier to search and control through a conversational interface.

What I built

An earlier WhatsApp bridge and a newer Telegram agent, alongside service wrappers, infrastructure configuration, and architecture documentation.

Engineering notes +

Decisions

Separate the agent, service adapters, infrastructure, and documentation. Keep user confirmation explicit for actions that change service state.

Evidence

Five public repositories expose the different parts of the system. Direct HTTP integrations and an MCP client scaffold are visible in source.

Current limits

The newer MCP discovery path is a stub, and the confirmed-action flow still needs end-to-end completion. These repositories should be presented as one evolving system.

Next focus

Complete and test one path: search → plan → confirm → execute → observe the result.
