02 / Selected work

Work at Cisco

Here are three projects I worked on at Cisco, with my role in each.

01 — AI Canvas

AI applications
Runtime and sessions

Featured work

Running agents in isolated sandboxes.

Connecting the agent runtime to sandbox execution, session storage, and workflow coordination.

The challenge

Agent sessions rely on several services working together. They need to stay coordinated when requests overlap or a service stops.

My part

I built the AgentCore management integration and a custom sandbox image. I also worked on session handling and workflow coordination with Redis and Temporal.

AgentCore / Redis / Temporal / Containers

More about the work

The problem

Moving toward sandbox-based execution introduces boundaries between orchestration, runtime management, and session state. Those boundaries need explicit coordination, particularly when multiple sessions or requests are active.

My contribution

  • Built the AgentCore management integration.
  • Developed a custom sandbox image for isolated agent execution.
  • Worked on the orchestrator with Redis and Temporal, including distributed concurrency and session management.
  • Tested session behavior by terminating orchestrator pods during active queries.

Working with the team

The wider AI Canvas platform and architecture were shared team work. My contribution focused on the integration, sandbox image, orchestration, and testing described here.

Validation

I used controlled pod termination during active queries to examine session continuity and routing across orchestrator instances. The focus was understanding behavior during disruption, alongside normal execution.

02 — Nexus Dashboard

Network software
Platform engineering

Network management infrastructure.

Building services used to manage large enterprise networks.

The challenge

Network management software needs secure service connections and a clear way to keep backup processes in sync.

My part

I worked on Kubernetes certificate management, connections to external certificate authorities, and a Java framework for choosing the active service.

Kubernetes / Java / PKI / Postgres

More about the work

The problem

Infrastructure services need explicit coordination and certificate lifecycles within a larger network management platform.

My contribution

I worked on certificate management for Kubernetes communications and external-CA integration, and implemented an SPI-based Java leader-election framework for active-standby configurations.

Working with the team

These were contributions within the Nexus Dashboard team. The broader product and infrastructure were developed collectively.

Validation focus

The important behaviors here are certificate lifecycle, trust between services, and coordination during leadership changes.

03 — Cloud APIC

Cloud networking
Network data

Mapping cloud network connections.

Collecting network configuration and showing how its parts connect.

The challenge

Cloud network settings make more sense when you can see how resources relate to each other.

My part

I built a Terraform collection service that fed configuration into a graph database for Cloud APIC / Cloud Network Controller.

Python / Terraform / Dgraph / Cloud networking

More about the work

The problem

A network model needs to represent resources and their relationships across cloud environments.

My contribution

I built a Terraform collection service feeding a unified graph database, as part of my cloud networking work.

Working with the team

The collection service was one contribution to the broader Cloud Network Controller product. The overall architecture and product were team work.

Validation focus

The important relationship is between collected configuration and its graph representation: the resources, their connections, and how those connections can be inspected.
